Integration with Autotask PSA

Veeam Service Provider Console offers integration with Datto Autotask PSA to combine the functionality of both products and consolidate client data in one place.

Integration offers the following capabilities:

  • Consolidated billing. You can consolidate information about services consumed by the clients into recurring service contracts in Autotask PSA.
  • Automated ticketing. You can automatically create service tickets in Autotask PSA based on Veeam Service Provider Console alarms.

This solution is intended for service providers who both:

  • Use Veeam Service Provider Console to manage and monitor data protection operations and services
  • Use Autotask PSA as the primary business management platform

This section assumes that you have a good understanding of Autotask PSA.

Integration Features

To provide integration with Autotask PSA, Veeam Service Provider Console uses an application plugin. The plugin allows two applications to communicate with each other through integration features — integration points that allow bidirectional synchronization of data.

The Autotask PSA plugin includes the following integration features:

  • Companies is the primary integration feature that allows you to select companies whose data you want to share between Veeam Service Provider Console and Autotask PSA. After you enable this feature, Veeam Service Provider Console retrieves a list of managed companies from Autotask PSA. You can then configure mapping to synchronize data about managed companies and enable further integration. A company that is not mapped is never billed and never generates tickets.
  • Ticketing feature allows you to create service tickets in Autotask PSA. The tickets are based on alarms triggered in Veeam Service Provider Console for a mapped company. After you enable this feature, Veeam Service Provider Console retrieves the ticket queues, statuses, priorities, sources and ticket types available in Autotask PSA. You can then configure ticket creation parameters.
  • Billing feature allows you to include information about type and quantity of Veeam-powered services consumed by the clients into contracts in Autotask PSA. After you enable this feature, Veeam Service Provider Console retrieves services and billing codes from the Autotask PSA service catalog and the contracts available for mapped companies. You can then configure mapping of services, and select contracts which will be used to bill measured consumption.
Note:

Integration features control synchronization, not navigation. All plugin pages remain available in the menu on the left whether or not the corresponding feature is enabled. A page whose feature is switched off displays an informational message at the top.

How the Integration Works

The plugin is a self-contained service that Veeam Service Provider Console starts, hosts and supervises. It is not installed separately, and it does not require Veeam Service Provider Console credentials to be specified — the plugin host provisions the plugin REST API key automatically at installation time. The only credentials you specify are the Autotask PSA ones.

Considerations and Limitations

Consider the following limitations of the integration.

  • Companies must exist on both sides. The plugin maps existing companies. It does not create company accounts in Veeam Service Provider Console, tenant accounts in Veeam Cloud Connect, or company records in Autotask PSA.
  • Configuration items are not created. The plugin does not create Autotask PSA configuration items for computers managed in Veeam Service Provider Console. Tickets identify the affected object by name in the ticket title and description instead.
  • Contract type. Only recurring service contracts can carry the services that the plugin maintains. Time and materials, fixed price and block-hour contracts are not supported.
  • Units are not converted. The plugin reports a number of units. Make sure that the unit of measure of the selected Autotask PSA service matches the unit of the mapped Veeam Service Provider Console service.
  • Client notifications are not managed by the plugin. If you want mapped companies to receive Veeam Service Provider Console alarm notifications in addition to Autotask PSA ticket notifications, configure alarm notifications in Veeam Service Provider Console.
  • Veeam Cloud Connect sites. Sites are not part of the company mapping model. On the Companies page, narrow down the list of companies by company name or by mapping status.

Installing the Autotask PSA Plugin

The Autotask PSA integration is delivered as a custom application plugin. You upload the plugin package in Veeam Service Provider Console, and Veeam Service Provider Console hosts the plugin service and serves the plugin UI inside the portal.

Installing the Plugin

To install the Autotask PSA plugin:

  1. Log in to Veeam Service Provider Console as a Portal Administrator.
  2. At the top right corner of the Veeam Service Provider Console window, click Configuration.
  3. In the configuration menu on the left, click Catalog.
  4. Click Upload Custom Plugin and select the VspcAutotaskPlugin.<version>.nupkg package.

    Veeam Service Provider Console validates the package signature, deploys the plugin and starts the plugin service. Installation progress is reported in the notification area.

  5. Wait until installation completes. The Autotask PSA plugin tile appears on the Catalog page.
  6. Click the Autotask PSA plugin tile to open the plugin.

At installation time, Veeam Service Provider Console registers the plugin and issues it a Veeam Service Provider Console REST API key automatically. Veeam Service Provider Console credentials are not requested at any point.

Note:

The plugin package must be signed. If the upload is rejected because of the package signature, sign the package with a code signing certificate trusted by the Veeam Service Provider Console server.

Upgrading the Plugin

You can upgrade the plugin from the Catalog page. Upgrade preserves all plugin data.

  1. Log in to Veeam Service Provider Console as a Portal Administrator.
  2. At the top right corner of the Veeam Service Provider Console window, click Configuration.
  3. In the configuration menu on the left, click Catalog.
  4. Click Upload Custom Plugin and select the newer plugin package.

    Because the plugin identifier does not change between versions, Veeam Service Provider Console replaces the installed version instead of adding a second plugin.

  5. Open the plugin and check the integration status. For details, see Plugin Status Page.

Company mappings, service mappings, per-company billing configuration, ticket links, ticketing and billing settings, the Autotask PSA connection and the activity log are preserved during an upgrade, because they are stored in C:\ProgramData\VspcAutotaskPlugin and not in the package folder that the upgrade replaces.

Note:

Tickets that are open at the moment of the upgrade are not affected. The alarm poller resumes from the state recorded in the plugin database, so an alarm that already has a ticket does not receive a second one.

Removing the Plugin

To remove the Autotask PSA plugin:

  1. Log in to Veeam Service Provider Console as a Portal Administrator.
  2. At the top right corner of the Veeam Service Provider Console window, click Configuration.
  3. In the configuration menu on the left, click Catalog.
  4. Remove the Autotask PSA plugin.

Before the plugin is removed, Veeam Service Provider Console instructs the plugin to purge its local data. The plugin deletes its database and stored credentials in response.

Note:

When you remove the plugin, consider that:

  • Nothing is deleted in Autotask PSA. Tickets, contracts, contract services and services created by the plugin remain in place.
  • The links between Veeam Service Provider Console alarms and Autotask PSA tickets are stored in the plugin database and are lost when plugin data is purged. If you install the plugin again, previously created tickets are no longer updated.

Enabling Autotask PSA Integration

To allow Veeam Service Provider Console to communicate with Autotask PSA, you must configure the application plugin and enable integration features.

Enabling Autotask PSA Integration

To enable integration with Autotask PSA, perform the following steps:

  1. Obtain Autotask PSA API credentials.
  2. Configure plugin connection.
  3. Enable integration features.

Step 1. Obtain Autotask API Credentials

In Autotask PSA, create an API-only user and save its user name, secret and integration code:

  1. Log in to Autotask PSA with an account that is allowed to create API users.
  2. In the navigation menu on the left, click Admin and select Organization Settings & Users.

    In some Autotask PSA versions, this menu item is named Account Settings & Users.

  3. Expand Resources/Users (HR) and click Resources/Users.
  4. Click New and select New API User.
  5. Specify the First Name, Last Name and Email Address of the API user.
  6. From the Security Level drop-down list, select API User (system).
  7. Under Credentials, click Generate Key and Generate Secret.

    The generated key is the API user name that you specify in the plugin. The generated secret is the password.

  8. Under API Tracking Identifier, select Custom (Internal Integration) and type a name for the integration, for example Veeam Service Provider Console.
  9. Click Save & Close.
  10. Copy and save the user name, the secret and the tracking identifier value.

    The secret cannot be displayed again after you close the form.

Note:

Treat the secret as a password. The plugin stores it encrypted with Windows DPAPI on the Veeam Service Provider Console server and never returns it to the browser, but anyone who holds the three values can access your Autotask PSA instance.

Step 2. Configure Plugin Connection

Configure Autotask PSA plugin connection in Veeam Service Provider Console:

  1. Log in to Veeam Service Provider Console.
  2. At the top right corner of the Veeam Service Provider Console window, click Configuration.
  3. In the configuration menu on the left, click Catalog.
  4. Click the Autotask PSA plugin tile.
  5. In the Autotask PSA Integration window, specify connection settings:
    • In the API user (email) field, type the user name generated for the API user at Step 1. Obtain Autotask API Credentials.
    • In the Secret field, type the generated secret.
    • In the Integration code field, type the value of the custom API tracking identifier.

    The Zone field is read-only. Veeam Service Provider Console detects the Autotask PSA zone for the specified API user automatically and fills in the field after a successful connection.

  6. Click Connect.
  7. In the Autotask PSA Integration window, check integration status.

    A successfully established connection will show the Healthy integration status, and the window will close.

Note:

The Autotask PSA Integration window opens automatically the first time you open the plugin while no Autotask PSA connection is configured. You can open it at any time on the Plugin Status page: next to Autotask zone, click Change.

If the plugin already stores a secret, the Secret field displays (unchanged). Leave the field empty to keep the stored secret, or type a new value to replace it.

Disconnecting Autotask PSA Plugin

If you no longer want to manage a Veeam Service Provider Console server in Autotask PSA, you can remove the plugin connection. After you disconnect the Autotask PSA plugin, all integration between Veeam Service Provider Console and Autotask PSA will be disabled: billing synchronization and ticket creation stop.

To disconnect the Autotask PSA plugin:

  1. Log in to Veeam Service Provider Console.
  2. At the top right corner of the Veeam Service Provider Console window, click Configuration.
  3. In the configuration menu on the left, click Catalog.
  4. Click the Autotask PSA plugin tile.
  5. In the menu on the left, click Plugin Status.
  6. Next to Autotask zone, click Change.
  7. In the Autotask PSA Integration window, click Disconnect.
  8. In the confirmation window, click Yes.

Disconnecting removes the stored Autotask PSA credentials. Company mappings, service mappings and ticket links are preserved, so if you connect the same Autotask PSA instance again, the configuration is restored without remapping.

Step 3. Enable Integration Features

Select information you want to share between Veeam Service Provider Console and Autotask PSA, and enable the necessary features:

  1. Log in to Veeam Service Provider Console.
  2. At the top right corner of the Veeam Service Provider Console window, click Configuration.
  3. In the configuration menu on the left, click Catalog.
  4. Click the Autotask PSA plugin tile.
  5. In the menu on the left, click Plugin Status.
  6. In the Integration Settings section, set toggles next to the necessary integration features to On.

    You can also click the Enable All link to enable all integration features. For details on integration features, see Integration Features.

Integration features are applied immediately. There is no separate save operation.

Note:

Toggles are unavailable until the Autotask PSA connection is configured. Until then, the Integration Settings section displays the Connect Autotask to enable integration features message.

Configuring Companies Integration

You can select companies whose data you want to share between Veeam Service Provider Console and Autotask PSA. To start sharing data of managed companies, you must configure mapping in Veeam Service Provider Console. Mapping enables further integration: only mapped companies are billed, and only mapped companies generate tickets.

Prerequisites

Before configuring integration of managed companies, check the following prerequisites:

  • Configure Autotask PSA plugin connection. For details, see Step 2. Configure Plugin Connection.
  • Enable the Companies integration feature. For details, see Step 3. Enable Integration Features.
  • The companies must already exist both in Veeam Service Provider Console and in Autotask PSA. For details, see Considerations and Limitations.

Companies Page

To open the page, click the Autotask PSA plugin tile in Configuration > Catalog, and then click Companies in the menu on the left.

Veeam Service Provider Console will display a list of all companies managed in Veeam Service Provider Console, along with the Autotask PSA company that each of them is mapped to.

Mapping Companies Automatically

Select this method if names of companies you manage in Veeam Service Provider Console are same or similar to their names in Autotask PSA.

To map companies automatically:

  1. Log in to Veeam Service Provider Console.
  2. At the top right corner of the Veeam Service Provider Console window, click Configuration.
  3. In the configuration menu on the left, click Catalog.
  4. Click the Autotask PSA plugin tile.
  5. In the menu on the left, click Companies.
  6. At the top of the list, click Map Companies Automatically.

    Veeam Service Provider Console will automatically detect companies in Autotask PSA whose names are the same as the names of companies configured in Veeam Service Provider Console, and will map them.

  7. In the Suggested Matches window, review the companies that could not be mapped automatically, and click a candidate to map the company to it.

    Each candidate is displayed with a match percentage.

How Matching Works

  • Company names on both sides are normalized before they are compared, so differences in case, punctuation and spacing do not prevent a match.
  • A company is mapped automatically only if exactly one unmapped Autotask PSA company matches its normalized name. Ambiguous names are never mapped automatically.
  • If no exact match is found, up to five Autotask PSA candidates with a name similarity of 72 % or higher are offered for review.
  • Companies that are already mapped are not processed, and an Autotask PSA company that is already mapped is not offered as a candidate.

Mapping Companies Manually

Select this method if names of companies you manage in Veeam Service Provider Console and their names in Autotask PSA do not match.

To map companies manually:

  1. Log in to Veeam Service Provider Console.
  2. At the top right corner of the Veeam Service Provider Console window, click Configuration.
  3. In the configuration menu on the left, click Catalog.
  4. Click the Autotask PSA plugin tile.
  5. In the menu on the left, click Companies.
  6. From the list of companies, select an unmapped company.

    To narrow down the list of companies, use the Company Name search or the Status filter.

  7. At the top of the list, click Map to.
  8. In the Map Company window, in the Autotask company field, start typing the name of the Autotask PSA company which you want to map, and select it from the list.

    The list is searchable and is filtered as you type.

  9. Click Map Company.
  10. Repeat steps 6–9 for all companies you want to map.
Note:

One Veeam Service Provider Console company can be mapped to one Autotask PSA company only. Autotask PSA companies that are already mapped are not displayed in the list.

Removing Mapping

If you want to stop sending data about services consumed by the company to Autotask PSA, you can remove mapping.

Note:

When you remove mapping for a company, consider that:

  • Billing configuration of the company in the plugin, that is the selected contract and the enabled services, will also be removed.
  • Contract services and quantities that have already been reported to Autotask PSA will not be removed, and tickets that are open in Autotask PSA will not be closed. Update these records in Autotask PSA manually if necessary.
  1. Log in to Veeam Service Provider Console.
  2. At the top right corner of the Veeam Service Provider Console window, click Configuration.
  3. In the configuration menu on the left, click Catalog.
  4. Click the Autotask PSA plugin tile.
  5. In the menu on the left, click Companies.
  6. From the list of companies, select one or more mapped companies.
  7. At the top of the list, click Remove Mapping.
  8. In the Remove Mapping window, click Yes.

Configuring Consolidated Billing

You can configure Veeam Service Provider Console to continuously send information to Autotask PSA about types and amount of services consumed by mapped companies. Autotask PSA will use this data to maintain quantities on recurring service contracts and generate consolidated invoices.

Note:

The amount of services is reported as the quantity of a contract service. The quantity depends on the type of service:

  • For services measured by actual numbers, the quantity is equal to the actual number of managed objects or amount of consumed space as of the last day for which Veeam Service Provider Console reported data.
  • For services measured for a billing period, the quantity is equal to the amount of resources consumed for the billing period.

Autotask PSA contracts will include the exact storage usage even if you have configured to round up storage usage costs in the subscription plan. The amount of services provided free of charge is defined by the selected subscription plan.

Make sure that the measurement unit of the selected Autotask PSA service is equal to the measurement unit of the mapped Veeam Service Provider Console service. For details, see Billable Service Catalog.

To configure billing consolidation, perform the following steps:

  1. Configure product mapping.

    Map services from Veeam Service Provider Console to services in the Autotask PSA service catalog.

  2. Select a contract.

    For every mapped company, select a contract which Autotask PSA will use to bill measured consumption.

  3. Enable services for the contract.

    Select the services that will be billed for the company.

Prerequisites

Before configuring consolidated billing, check the following prerequisites:

  • Configure Autotask PSA plugin connection. For details, see Step 2. Configure Plugin Connection.
  • Enable the Companies and Billing integration features. For details, see Step 3. Enable Integration Features.
  • Configure integration for the companies for which you want to consolidate billing data. For details, see Configuring Companies Integration.
  • The companies for which you want to consolidate billing data must have at least one recurring service contract in Autotask PSA.
  • A subscription plan must be configured in Veeam Service Provider Console. The plugin uses it as the price reference for services that it creates in Autotask PSA.

How Quantities Are Calculated

The plugin reads usage counters from Veeam Service Provider Console, converts them into billable units, and keeps the quantity of every Autotask PSA contract service aligned with the measured value. Quantities are maintained through contract service adjustments, which record the change in units rather than an absolute value.

Two aggregation rules apply, depending on the service:

  • Services measured by actual numbers. The quantity is the most recently reported value: the actual number of managed objects, or the amount of consumed space, as of the last day for which Veeam Service Provider Console reported data.
  • Services measured for a billing period. The quantity is the total amount consumed during the billing period. Data transfer out is measured this way.

Storage counters are reported by Veeam Service Provider Console in bytes and are converted to gigabytes before they are sent to Autotask PSA.

Note:

Contracts have their own start and end dates in Autotask PSA. An adjustment whose effective date is outside the contract period is rejected by Autotask PSA, and the corresponding line is reported with the error status in the synchronization results.

Step 1. Configure Product Mapping

Enable Veeam Service Provider Console services that you want to bill in Autotask PSA:

  1. Log in to Veeam Service Provider Console.
  2. At the top right corner of the Veeam Service Provider Console window, click Configuration.
  3. In the configuration menu on the left, click Catalog.
  4. Click the Autotask PSA plugin tile.
  5. In the menu on the left, click Billing.
  6. Navigate to the Product Mapping tab.
  7. At the top of the page, from the Use this subscription plan to define price for the service drop-down list, select a subscription plan from which you want to obtain service prices.
  8. Check the remaining billing settings and click Apply:
    • Use this unit of measure for all allocated storage — fixed to TB in this version.
    • Billing period start day — day of month the billing period starts, from 1 to 28. Default: 1.
    • Daily sync hour (UTC) — hour at which automatic billing synchronization runs. Default: 1.
    • Default billing code (for created services) — Autotask PSA allocation code assigned to services that the plugin creates.
  9. Under the name of a Veeam Service Provider Console service group, set a toggle to Enabled.
  10. For each service in the service group, select a necessary option from the Mode drop-down list:
    • Existing Autotask service

      In this case, Veeam Service Provider Console will map the service to the selected active Autotask PSA service.

    • Create new service

      In this case, Veeam Service Provider Console will create a new service in the Autotask PSA service catalog and map it to the selected service. Specify the New service name and Unit price. You can change this price at any time in the Autotask PSA catalog.

    • Do not bill

      In this case, Veeam Service Provider Console will skip the selected service and will not map it to any service in Autotask PSA.

  11. Click Save in every service row that you have changed.

Step 2. Select a Contract

Select contracts which will be used to bill Veeam Service Provider Console services:

  1. On the Billing page, navigate to the Contracts tab.
  2. From the list of mapped companies, select a company for which you want to configure billing, and click Configure in its row.
  3. In the Contracts window, from the Contract drop-down list, select a necessary contract.

    If the company has no contracts in Autotask PSA, the window displays the No contracts found for this company in Autotask message. Create a recurring service contract in Autotask PSA, and then click Refresh Data on the Contracts tab.

  4. Proceed to Step 3. Enable Services for the Contract without closing the window.

Step 3. Enable Services for the Contract

Select the services that will be billed on the selected contract:

  1. In the Contracts window, under Enabled Services, select the services that you want to bill for this company.

    Only the services that you have mapped on the Product Mapping tab are displayed. If the list is empty, return to the Product Mapping tab and map at least one service.

  2. Click Save.
  3. Repeat the procedure for all companies for which you want to consolidate billing data.

Veeam Service Provider Console will attach the mapped services to the selected contract and start sending information about the quantity of consumed services to Autotask PSA.

To stop billing a company without removing its company mapping, click Disable Billing in the company row, and then click Yes.

Previewing and Running Synchronization

Billing synchronization runs automatically once a day at the configured hour. You can also run it manually, and you can check what a run will do before any data is sent to Autotask PSA.

CommandDescription
Preview (Dry Run)Calculates the measured units, the current units and the resulting difference for every configured company and service, and records the outcome in the billing history without sending any data to Autotask PSA. Use this command to validate a new configuration.
Sync NowPerforms the same calculation and reports the resulting contract service adjustments to Autotask PSA. Veeam Service Provider Console will ask you to confirm the operation.
Refresh DataRetrieves mapped companies and their Autotask PSA contracts. The command displays the time of the last synchronization.

Both commands display the Synchronization results list.

ColumnDescription
CompanyVeeam Service Provider Console company.
ServiceVeeam Service Provider Console service.
CurrentUnits currently recorded on the Autotask PSA contract service.
MeasuredUnits calculated from Veeam Service Provider Console usage data.
DeltaDifference that will be, or that was, reported to Autotask PSA.
StatusResult of the operation: adjusted — reported to Autotask PSA; planned — result of a dry run; no-change — the difference was zero and nothing was reported; skipped — the line was not eligible for reporting; error — Autotask PSA rejected the operation.
MessageDetails for the line, including the Autotask PSA error message where applicable.
Note:

Adjustments are reported with the effective date set to the current day in UTC. Running synchronization twice on the same day is safe: the second run calculates a difference of zero for the lines that have not changed and reports nothing.

Configuring Automated Ticketing

You can configure Veeam Service Provider Console to send information about triggered alarms to Autotask PSA and to create service tickets based on alarm data.

Prerequisites

Before configuring automated ticketing, check the following prerequisites:

  • Configure Autotask PSA plugin connection. For details, see Step 2. Configure Plugin Connection.
  • Enable the Companies and Ticketing integration features. For details, see Step 3. Enable Integration Features.
  • Configure integration for the companies for which you want to create tickets automatically. For details, see Configuring Companies Integration. Alarms triggered for unmapped companies never create tickets.
  • In Autotask PSA, the queue on which you want to create tickets automatically must exist, and the ticket statuses that you want to use for new and for closed tickets must be available.

Configuring Ticket Settings

To configure parameters of tickets created by Veeam Service Provider Console:

  1. Log in to Veeam Service Provider Console.
  2. At the top right corner of the Veeam Service Provider Console window, click Configuration.
  3. In the configuration menu on the left, click Catalog.
  4. Click the Autotask PSA plugin tile.
  5. In the menu on the left, click Ticketing.
  6. At the top of the page, click Ticket Settings and configure ticketing settings as described in the table below.
  7. Click Save.

Queue, status, priority, source and ticket type values are retrieved from your Autotask PSA instance when the window opens. Each drop-down list is searchable.

SettingDescription
QueueAutotask PSA queue on which tickets will be created.
Status for new ticketsStatus assigned to a ticket when Veeam Service Provider Console creates it.
Status for closed ticketsStatus assigned to a ticket when Veeam Service Provider Console closes it because the alarm used to create this ticket was resolved.
Priority — Warning alarmsPriority that must be assigned to tickets created for triggered Warning alarms.
Priority — Error alarmsPriority that must be assigned to tickets created for triggered Error alarms.
SourceOptional. Autotask PSA ticket source recorded on created tickets.
Ticket typeOptional. Autotask PSA ticket type recorded on created tickets.
Delay before ticket (minutes)Time period after which the ticket for a triggered alarm must be created. An alarm that is resolved within this period never becomes a ticket, which suppresses tickets for transient conditions. Default: 5.
Due date offset (hours)The ticket due date is set to the creation time plus this offset. Autotask PSA requires a due date on most ticket categories. Default: 24.
Alarm poll interval (seconds)Period at which Veeam Service Provider Console is polled for alarm state. Default: 120. Values are limited to the range from 30 to 3600.
Close ticket when alarm resolvesWhen an alarm is resolved in Veeam Service Provider Console, the status of the ticket created for this alarm changes to the status for closed tickets. Enabled by default.
Resolve alarm when ticket closesWhen a ticket is closed in Autotask PSA, the alarm used to create this ticket is resolved in Veeam Service Provider Console. Enabled by default.

Note:

The Status for new tickets and Status for closed tickets settings must be set to different Autotask PSA statuses. If both settings use the same status, the plugin cannot distinguish an open ticket from a closed one: every new ticket is reported as already closed, and duplicate tickets are created for the same alarm. Veeam Service Provider Console does not save such a combination, and stops the alarm poll if it is detected.

Enabling Alarms

To enable automatic creation of tickets based on Veeam Service Provider Console alarms:

  1. Log in to Veeam Service Provider Console.
  2. At the top right corner of the Veeam Service Provider Console window, click Configuration.
  3. In the configuration menu on the left, click Catalog.
  4. Click the Autotask PSA plugin tile.
  5. In the menu on the left, click Ticketing.

    Veeam Service Provider Console will display a list of all enabled alarms, except alarms for the Cloud Gateway, Internal, Plugin, Site and User objects.

  6. On the Alarms tab, from the list of alarms, select alarms for which you want to create tickets.

    To narrow down the list of alarms, use the Alarm Name search or the Status filter.

  7. At the top of the list, click Enable.

To stop creating tickets for an alarm, select the alarm and click Disable. To retrieve the list of alarms from Veeam Service Provider Console again, click Refresh Data.

Note:

Veeam Service Provider Console records the moment when ticketing is enabled for the first time. Alarms that were already triggered before that moment do not create tickets. This prevents a backlog of historical alarms from being reported to your Autotask PSA queue when the integration is enabled.

Ticket and Alarm Lifecycle

Veeam Service Provider Console polls alarm state at the configured interval and reconciles both sides at every poll:

  • An alarm triggered for a mapped company on an enabled alarm enters the Pending state. If the alarm is resolved before the delay period elapses, it changes to the Cancelled state and no ticket is created.
  • After the delay period elapses, a ticket is created in the configured queue with the status for new tickets, the priority that matches the alarm severity, and a due date offset from the creation time. The ticket contains the company, the alarm name and the affected object.
  • If the same alarm is triggered again while its ticket is open, a note is added to the existing ticket instead of creating a second ticket.
  • When the alarm is resolved, or acknowledged if the Acknowledged counts as resolved setting is enabled, the status of the ticket changes to the status for closed tickets.
  • Conversely, when you close the ticket in Autotask PSA, Veeam Service Provider Console resolves the alarm used to create this ticket.

The synchronization period for these actions is equal to the alarm poll interval, so a change made on either side is reflected on the other side within one poll. For details, see Refreshing Data.

To synchronize the necessary data immediately, you can refresh it manually:

Obtaining Plugin Logs

Required Privileges

To perform this task, a user must have the following role assigned: Portal Administrator.

Obtaining Plugin Logs

The plugin writes log files on the machine that hosts the Veeam Service Provider Console Server component. The log files are located in the following folder:

C:\ProgramData\VspcAutotaskPlugin\logs

The log contains records about plugin startup, every request that the portal sends to the plugin and its result, Autotask PSA API errors, and the result of every scheduled and manual synchronization. If the plugin cannot start, for example because the plugin package was deployed incompletely, the reason is written to the startup-error.log file in the same folder.

The plugin also provides a log archive to the Veeam Service Provider Console plugin host, which contains the activity of the last 30 days.

Note:

Log files may contain company names, alarm messages and Autotask PSA entity identifiers. Log files do not contain the Autotask PSA secret. Review the collected logs before you send them outside your organization.

Troubleshooting

The following table describes the most common issues and the way to resolve them.

IssueCause and resolution
Veeam Service Provider Console reports that a ticket is closed, but the ticket remains open in Autotask PSA, and duplicate tickets are created for the same alarm. The Status for new tickets and Status for closed tickets settings use the same Autotask PSA status. Select two different statuses in the Ticket Settings window. For details, see Configuring Ticket Settings.
The list of companies is empty. The company lists have not been retrieved yet, or the connection to Autotask PSA is not healthy. Click Refresh Data, and then check the status on the Plugin Status page.
The Contracts window displays no contracts for a company. The mapped Autotask PSA company has no contracts, or none of its contracts is a recurring service contract. Create a recurring service contract in Autotask PSA, and then click Refresh Data on the Contracts tab. Note that the Autotask PSA company identifier 0 is a valid identifier: it is the record of your own organization, and its contracts are listed as usual.
Queue, status and priority lists in the Ticket Settings window are empty. The values are retrieved from Autotask PSA when the window opens. If the connection is not healthy, the lists remain empty and the fields are unavailable. Configure the connection first.
Billing lines are reported with the error status. Check the message in the results list. The most common causes are an effective date outside the contract period, a contract that is not a recurring service contract, and an Autotask PSA service that the API user cannot modify.
Reported quantities of a storage service are unexpectedly high or low. Check that the measurement unit of the Autotask PSA service matches the unit of the mapped Veeam Service Provider Console service. Veeam Service Provider Console storage counters are converted to gigabytes, so an Autotask PSA service priced per terabyte will be billed incorrectly.
Opening a plugin page returns an authorization error. The plugin admits only Portal Administrator and Portal Operator users. Log in with an account that has one of these roles assigned.
