# VSPC Plugin Packaging

This folder builds the **uploadable VSPC custom plugin package** from the integration service,
following the official *Veeam Service Provider Console Plugin Template Guide* (KB4311 SDK —
`Veeam.VSPC.Plugin.Template.zip` — download it from KB4311 into `sdk-drop/` if you want it at hand; it is not part of this repository).

## Build the package

```powershell
..\build.ps1            # repo root: unit tests + package (recommended)
.\plugin\build-plugin.ps1   # package only
# → build\VspcAutotaskPlugin.<version>.nupkg  (signed)
```

The script:
1. Builds the plugin UI (React / Veeam UIKit) in `src/UI`: `npm install` on the first run, then
   `npm run build:production`. Requires Node 20 and the Veeam UIKit tarballs in `src/UI/vendor/`
   (from the KB4311 SDK; not redistributed in this repository).
2. Publishes the service as a **self-contained win-x64** app (no runtime needed on the VSPC server)
   into `content/any/any/service/`.
3. Copies the built UI bundle into `content/any/any/ui-content/` and into the service's `wwwroot/`
   (the service serves the same page for proxied requests).
4. Adds `ui-layout-config/page-config.json` (from the UI build, falling back to `plugin/page-config.json`),
   `rest-specification/api.yml` and `plugin.manifest.xml` (plus defensive copies of the manifest/nuspec
   next to the executable so the service finds them in any deployment layout).
5. Packs everything with `AutotaskPsa.nuspec` via `dotnet pack`.
6. Signs the `.nupkg` (**required by VSPC**). A self-signed code-signing certificate
   (`plugin/sign.p12`, password `CertificatePassword123`, excluded from the repository) is generated
   on the first run — pass `-CertPath`/`-CertPassword` to use your own.

## Install in VSPC

**Configuration → Catalog → Upload Custom Plugin** → select the `.nupkg` → watch the notification
bell for installation progress. Because `serviceApiKeyObtainMethod` is `autoGenerated`, VSPC
issues the plugin a REST API key at install time.

## What happens at runtime (plugin mode)

VSPC launches `VspcAutotaskPlugin.exe` (`serviceHosting: outProcess`) and the service detects
plugin hosting via the `GRPC_PLUGIN_REGISTRY_ADDRESS`/`GRPC_PLUGIN_REGISTRY_PORT` environment
variables. It then:

- binds `http://127.0.0.1:33847` (the `serviceHttpPort` from `plugin.manifest.xml`),
- registers with the VSPC **Plugin Registry** (gRPC `register` + manifest with file hashes),
- calls `getApiKey` and `discoverService(Rest)` to **auto-provision its VSPC REST connection**
  (no manual VSPC credentials needed — only Autotask credentials are entered in the UI),
- serves the package tree at `/content/` so VSPC can request manifest-declared files,
- answers the host-management endpoints declared in the manifest:
  `GET /api/v1/healthcheck`, `GET /api/v1/readiness` (empty 200s),
  `GET /api/v1/logs` (ZIP of the last 30 days of activity),
  `DELETE /api/v1/localdata` (full data purge before uninstall),
- stores its state in `%ProgramData%\VspcAutotaskPlugin` so upgrades don't lose mappings.

The UI is served by VSPC at `/plugins/7A4C3E529D144F6BB7A152AE23C90D11/index.html`, and every
endpoint declared in `rest-specification/api.yml` is proxied under the same prefix. Requests
arrive with the **X-User-Uid** header set by VSPC; the service verifies the user against VSPC and
only admits **Portal Administrator / Portal Operator** roles (no separate plugin password in
plugin mode). The SPA auto-detects the `/plugins/{id}/` prefix.

## Versioning

- `pluginId` (`7A4C3E529D144F6BB7A152AE23C90D11`) is the permanent identity — **never change it**.
- To ship an update: bump `<version>` in `plugin/AutotaskPsa.nuspec` (and the csproj `<Version>`),
  rebuild, re-upload. Data in `%ProgramData%\VspcAutotaskPlugin` carries over.
- The port `33847` can be changed in `plugin/plugin.manifest.xml` if it collides on your server.

## Verified

Verified against live VSPC 9.2 and 9.3 installations: Catalog upload, gRPC registration with the
Plugin Registry, API-key auto-provisioning, UI proxying under `/plugins/{id}/`, and the Autotask
integration features end to end (company mapping, ticketing, billing). If the upload validator
rejects the self-signed signature, re-sign with a CA-issued code-signing certificate.

## Ad-hoc debugging without packaging

VSPC also supports ephemeral plugin registration for development (see the template guide's
"Debugging with Remote VSPC Service": SSH-tunnel ports 1983/1984/1987/5017 and your plugin port,
then run the service from `plugin/staging/content/any/any/service/` with
`GRPC_PLUGIN_REGISTRY_ADDRESS` pointing at the tunneled registry).
