Configuring Automated Ticketing

You can configure Veeam Service Provider Console to send information about triggered alarms to Autotask PSA and to create service tickets based on alarm data.

Prerequisites

Before configuring automated ticketing, check the following prerequisites:

  • Configure Autotask PSA plugin connection. For details, see Step 2. Configure Plugin Connection.
  • Enable the Companies and Ticketing integration features. For details, see Step 3. Enable Integration Features.
  • Configure integration for the companies for which you want to create tickets automatically. For details, see Configuring Companies Integration. Alarms triggered for unmapped companies never create tickets.
  • In Autotask PSA, the queue on which you want to create tickets automatically must exist, and the ticket statuses that you want to use for new and for closed tickets must be available.

Configuring Ticket Settings

To configure parameters of tickets created by Veeam Service Provider Console:

  1. Log in to Veeam Service Provider Console.
  2. At the top right corner of the Veeam Service Provider Console window, click Configuration.
  3. In the configuration menu on the left, click Catalog.
  4. Click the Autotask PSA plugin tile.
  5. In the menu on the left, click Ticketing.
  6. At the top of the page, click Ticket Settings and configure ticketing settings as described in the table below.
  7. Click Save.

Queue, status, priority, source and ticket type values are retrieved from your Autotask PSA instance when the window opens. Each drop-down list is searchable.

SettingDescription
QueueAutotask PSA queue on which tickets will be created.
Status for new ticketsStatus assigned to a ticket when Veeam Service Provider Console creates it.
Status for closed ticketsStatus assigned to a ticket when Veeam Service Provider Console closes it because the alarm used to create this ticket was resolved.
Priority — Warning alarmsPriority that must be assigned to tickets created for triggered Warning alarms.
Priority — Error alarmsPriority that must be assigned to tickets created for triggered Error alarms.
SourceOptional. Autotask PSA ticket source recorded on created tickets.
Ticket typeOptional. Autotask PSA ticket type recorded on created tickets.
Delay before ticket (minutes)Time period after which the ticket for a triggered alarm must be created. An alarm that is resolved within this period never becomes a ticket, which suppresses tickets for transient conditions. Default: 5.
Due date offset (hours)The ticket due date is set to the creation time plus this offset. Autotask PSA requires a due date on most ticket categories. Default: 24.
Alarm poll interval (seconds)Period at which Veeam Service Provider Console is polled for alarm state. Default: 120. Values are limited to the range from 30 to 3600.

Resolve alarm when ticket closesWhen a ticket is closed in Autotask PSA, the alarm used to create this ticket is resolved in Veeam Service Provider Console. Enabled by default.

Acknowledged counts as resolvedAlarms acknowledged in Veeam Service Provider Console are processed in the same way as resolved alarms when tickets are closed. Enabled by default.
Note:

The Status for new tickets and Status for closed tickets settings must be set to different Autotask PSA statuses. If both settings use the same status, the plugin cannot distinguish an open ticket from a closed one: every new ticket is reported as already closed, and duplicate tickets are created for the same alarm. Veeam Service Provider Console does not save such a combination, and stops the alarm poll if it is detected.

Enabling Alarms

To enable automatic creation of tickets based on Veeam Service Provider Console alarms:

  1. Log in to Veeam Service Provider Console.
  2. At the top right corner of the Veeam Service Provider Console window, click Configuration.
  3. In the configuration menu on the left, click Catalog.
  4. Click the Autotask PSA plugin tile.
  5. In the menu on the left, click Ticketing.

    Veeam Service Provider Console will display a list of all enabled alarms, except alarms for the Cloud Gateway, Internal, Plugin, Site and User objects.

  6. On the Alarms tab, from the list of alarms, select alarms for which you want to create tickets.

    To narrow down the list of alarms, use the Alarm Name search or the Status filter.

  7. At the top of the list, click Enable.

To stop creating tickets for an alarm, select the alarm and click Disable. To retrieve the list of alarms from Veeam Service Provider Console again, click Refresh Data.

Note:

Veeam Service Provider Console records the moment when ticketing is enabled for the first time. Alarms that were already triggered before that moment do not create tickets. This prevents a backlog of historical alarms from being reported to your Autotask PSA queue when the integration is enabled.

Ticket and Alarm Lifecycle

Veeam Service Provider Console polls alarm state at the configured interval and reconciles both sides at every poll:

  • An alarm triggered for a mapped company on an enabled alarm enters the Pending state. If the alarm is resolved before the delay period elapses, it changes to the Cancelled state and no ticket is created.
  • After the delay period elapses, a ticket is created in the configured queue with the status for new tickets, the priority that matches the alarm severity, and a due date offset from the creation time. The ticket contains the company, the alarm name and the affected object.
  • If the same alarm is triggered again while its ticket is open, a note is added to the existing ticket instead of creating a second ticket.
  • When the alarm is resolved, or acknowledged if the Acknowledged counts as resolved setting is enabled, the status of the ticket changes to the status for closed tickets.
  • Conversely, when you close the ticket in Autotask PSA, Veeam Service Provider Console resolves the alarm used to create this ticket.

The synchronization period for these actions is equal to the alarm poll interval, so a change made on either side is reflected on the other side within one poll. For details, see Refreshing Data.

Recent Ticket Activity

The Recent Ticket Activity tab of the Ticketing page displays the operations performed by the ticket engine. Use this tab to check that the integration works as expected.

ColumnDescription
StatusState of the link between the alarm and the ticket: Pending, Open, Closed, Cancelled or Error.
TicketNumber of the Autotask PSA ticket.
CompanyCompany for which the alarm was triggered.
AlarmAlarm that was triggered.
ObjectManaged object associated with the triggered alarm.
UpdatedTime when the state last changed.
MessageLast reported status, or the error message if the state is Error.

To narrow down the list, use the search field to find a company, alarm, object or ticket number, and the Status filter to display a specific state. To run an alarm poll immediately instead of waiting for the configured interval, click Poll Alarms Now. Veeam Service Provider Console will report how many alarm events were processed and how many tickets were created, closed and updated with notes.

Refreshing Data

After you configure integration features, the data between Veeam Service Provider Console and Autotask PSA will be synchronized automatically. To synchronize the necessary data immediately, you can refresh it manually.

Synchronization Intervals

DataIntervalNotes
Company lists from both applicationsEvery 4 hours Used on the Companies page and in the mapping windows.
Alarm state and ticket reconciliationEvery 120 seconds Configured by the Alarm poll interval (seconds) setting in the Ticket Settings window, from 30 to 3600 seconds.
Billing reconciliationOnce a day At the hour configured by the Daily sync hour (UTC) setting on the Product Mapping tab. Default: 1.

Refreshing Data Manually

To synchronize the necessary data immediately, you can refresh it manually:

  1. Log in to Veeam Service Provider Console.
  2. At the top right corner of the Veeam Service Provider Console window, click Configuration.
  3. In the configuration menu on the left, click Catalog.
  4. Click the Autotask PSA plugin tile.
  5. In the menu on the left, click the section for which you want to refresh data: Companies, Ticketing, Billing (Contracts tab).
  6. At the top of the page, click Refresh Data.

Every Refresh Data command displays the time of the last synchronization for the corresponding page.

Note:

Two more commands are available in addition to Refresh Data:

  • Poll Alarms Now on the Ticketing > Recent Ticket Activity tab runs a full ticket reconciliation immediately.
  • Sync Now on the Billing > Contracts tab runs billing reconciliation immediately. For details, see Previewing and Running Synchronization.
